bump: minor

Commands whose work can outlive one tool call are now re-callable: a new `orch.sh verification run <command>`, and the existing `review ci` and `spec-review wait`. A call waits at most `ORCH_WAIT_BLOCK` seconds (570 by default). When the work is done it prints the work's output and exits with its status, as before; when the work is still going it prints `orch: still running after <n>s - run the same command again` on stderr, nothing on stdout, and exits 75. `verification run` runs its command detached in a process group of its own, so the run survives the call that started it. Running the same command again on the same HEAD and working tree waits for the same run instead of starting a second one, and a run whose tree has since changed is stopped and replaced. A detached run is stopped at a ceiling, the new per-clone `orchestrator.verification.timeout` setting (3600 seconds by default), and delivered as a failed run. A verification command that itself exits 75 is delivered as exit 1. `review ci` and `spec-review wait` keep their 900 s totals across calls. Every agent and skill that runs a verification now runs it through `verification run`, and the Bash hook's pgrep/pkill denial now tells a session to run a re-callable command again. "Re-callable command" has a glossary entry, and ADR-0065 records the decision, amending ADR-0058 and ADR-0063.
