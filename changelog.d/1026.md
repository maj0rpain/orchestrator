A filed finding's severities and label rules now live in one module, `filed-finding.sh`, with each filed severity's label colour and description in one table. The move itself changes no behaviour; `review file`'s new grammar is below (#1026).

An open issue is read in one place, `open_issue_read`, by finding triage's scan, the bundle-member check, `bundle --into`, init's adopted-issue gate and `issue triage`; every message stays word for word (#1026).

A filed finding's issue body is rendered from its parts and parsed back in one module, and finding triage reads Location and PR through that parser; the scan's output is unchanged (#1026).

`review file` now takes a finding's parts as flags - `--finding-file`, `--severity-reason`, `--location`, `--sha`, `--pr`, `--why` and an optional `--spec-question` - in place of `--body-file`, renders the body itself, and refuses before any write a finding whose body does not parse back to its parts (#1026).
