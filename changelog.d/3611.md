`spec-review apply`'s autopilot hold run builds the held blocks in apply's own shell and passes them to `spec_round_hold <dir> <blocks>` as an argument, so a failing `awk` or a `grep` read error on batch.md dies with `could not read <dir>/batch.md - nothing written to GitHub` instead of leaving fundamental.md incomplete. Apply reads the `--host-fallbacks` file, a resumed apply's changelog.md and the saved apply-answer through `file_read`, so an unreadable one dies with its own `orch:` message instead of a stray `cat:` error. The batch.md content wrapper is renamed `spec_review_batch_content`, the offline ticket check tests for a text item in one switch, `apply_prints_one` is built on `sra_refused`, the state-precedence cases load orch.sh once, and the spec tests' "today's" labels name their message.
