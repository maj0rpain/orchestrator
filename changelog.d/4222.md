bump: patch

`orch.sh doctor` and its alias `orch.sh health` now run as a Python converted
noun, from `scripts/orch_py/orch/doctor.py`. `--env` and `--flow`, the usage
line, every check's `ok` / `warn` / `FAIL` line and remedy, their order and
groups, the skip report, the tally and the exit code are unchanged, in plain and
autopilot sessions, and a closed stdout pipe ends it silently. Without python3,
or with one older than 3.9, doctor now dies naming the install
(`brew install python3, or your platform's package manager`) rather than
pointing at itself; every other converted noun still points at `orch.sh doctor`.
The python3 check is now an ok-only line, and the bash check reports the bash
that ran `orch.sh`. Doctor's five Python bridges (`agent check_settings`,
`ticket-worktree worktrees_left`, `review doctor_terminal`, `doctor_ci` and
`doctor_standards`) become in-process calls and are removed, as is the glossary
check's child `orch.sh glossary terms`. The bash `doctor` module, its test
sections and the bash helpers only doctor called are removed, and the Python
gh, git, handoff, standing, liveness, side-checkout, repo and triage labels
modules gain the reads doctor reaches.
