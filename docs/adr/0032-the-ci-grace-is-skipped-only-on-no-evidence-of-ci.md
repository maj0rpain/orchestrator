# The CI grace is skipped only on no evidence of CI, and runs from the push

GitHub has no "does this repo have CI" answer: checks exist only once something reports them, so zero checks just after a push is ambiguous. `review ci` keeps its 60-second grace but counts it from the head's push time, read from the remote-tracking ref's reflog, falling back to the call time. It skips the grace entirely only when no workflow files are in the head tree, no required checks are set on the base branch by classic branch protection or a ruleset, and no check-run or status exists on an earlier PR commit or the base tip. Any signal present, or unreadable, keeps the grace. The errors are asymmetric - a false "has CI" costs a minute, a false "no CI" marks a PR ready over checks nobody verified - so the shortcut is taken only on the safe side.
