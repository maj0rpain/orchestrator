# Sharing the `--jq` argument scan between the gh test stubs

This project does not extract a shared helper for the few lines that find
the value after `--jq` in a stubbed `gh` call, even though the scan appears
in both `scripts/test/gh_adapter_fake.sh` and the fake `gh` executable that
`scripts/test/orch_test.sh` writes, and in a third variant in the fake's
`adapter_pr_list`.

## Why this is out of scope

The two stubs are different kinds of thing. `gh_adapter_fake.sh` is a file of
shell functions sourced in place of the real adapter. The `orch_test.sh` stub
is a standalone `gh` program on the test `PATH`, generated by the suite, with
no reliable way to find a sibling file to source. Sharing the scan would mean
a new test-support file, located from inside a generated script, just to save
three lines:

```sh
q=.; prev=
for b in "$@"; do [ "$prev" = --jq ] && q="$b"; prev="$b"; done
```

If one copy ever drifted, the behaviour tests that run the request's `--jq`
through real jq would fail, because the formatting under test is `orch.sh`'s.
The same trade-off is recorded for the state fixture in
`test-fixture-state-writer-copy.md`.
